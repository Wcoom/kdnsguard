# kdnsguard 0.2.0 —— 内核态 DNS，KernelSU 模块形态

把全局 DNS（接管 / 缓存 / 同名合并 / DoH 上游）放进 Linux 内核，用户空间只调接口。
本版本交付的是**树外 KO + KernelSU 模块**：开机加载后，内核自己完成接管，**不需要任何
开机脚本、也不需要代理进程活着**。

## 装什么

`kdnsguard-ksu-0.2.0.zip` —— KernelSU/Magisk 模块。装法：KernelSU 应用里「安装模块」，
或 `ksud module install kdnsguard-ksu-0.2.0.zip`。卸载：应用里移除模块即可（模块自带
`disable` 开关）。

## 开机会发生什么

```
KernelSU 模块 post-fs-data → insmod kdnsguard.ko allow_intercept=1 auto_start=1
                           → mknod /dev/kdnsguard（主设备号读 /proc/devices）
内核（模块自己）：内建信任锚已加载（1 张）
                自启：内核态 DNS 已接管 53（无用户空间参与，第 N 次尝试）
```

三件事都在模块内部，这是「开机不依赖脚本」的全部内容：

| 事项 | 落点 |
|---|---|
| 信任锚（钉子根证书） | 编进 `.ko`（`-DKDG_EMBED_CA`） |
| 所有权事务 PREPARE→COMMIT | 编进 `.ko`（`-DKDG_AUTO_START`）：延迟工作带重试，网络就绪前反复尝试；ownership 非 NONE 时让位给持有者，对方释放后下一拍接管 |
| insmod / mknod | KernelSU 模块脚本（内核做不了这两件） |

**引导保护**：`post-fs-data` 先落 `.boot` 标记、`service.sh` 开机完成后清除。下次开机若
仍看到标记，说明上一次加载把设备拖住了 —— 立刻自我停用，**绝不进入开机循环**。恢复：
删掉模块目录下的 `disable`。

## 它怎么解析

- 上游：`https://d6382545.6.00p.net/gd/h596382545`，内核里的 TLS 1.3 + HTTP/2；
  支持 HTTP/3（QUIC v1/v2，内核内自带握手），UDP/443 被封时自动回落 H2（失败后退避 60 秒）。
- App 明文 53 与热点客户端 53 都由 Netfilter NAT 送进内核 listener；热点客户端拿到的是
  **真实 IP**（不再 FakeIP，前提是代理侧配置为 `dns-mode: off`）。
- 解析结果会发布进一张 BPF 哈希表（`地址 → 域名哈希 + TTL`），供 eBPF 在 connect 时按哈希
  匹配域名，不必回用户空间问。

## 边界（方案原文的线，没有变）

- **上游是 H2 还是 H3 由网络决定**：能走 QUIC 就走 H3，否则 H2。两者都在内核里。
- **App 的加密内置 DNS 拦不住内容**：内核解不开 App 信任的证书。能做的只是拒绝
  （853 直接拒；已知公共 DoH 的 443 按 IP/域名拒），逼它回落到明文 53 —— 落回来就由内核解析。
- **私人 DNS 必须保持 off**：strict 走 853，内核不能接管 853（证书语义）。
- 能耗无结论：本机没有功率计，按方案 §17.4 不作任何更低能耗的宣传。

## 配套

`kdgctl`（诊断客户端，随模块附带）：`health` 看 ownership/doh_ok/bpf_published 等，
`query <域名>` 直接问内核，`bpftest <秒>` 验证「内核 → BPF 表」这条链路。
